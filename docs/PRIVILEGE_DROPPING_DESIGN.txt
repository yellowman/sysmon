Privilege Dropping Design and Future Enhancements

Problem Statement

Sysmon needs root privileges for two operations:
1. ICMP socket operations - Requires CAP_NET_RAW capability (or root)
2. Binding privileged ports - If listen port < 1024

However, running the entire daemon as root violates the principle of least privilege and creates a security risk.

Current Implementation (Partial Solution)

What Works
  - ? Drops privileges to 'nobody' if ICMP is disabled
  - ? Only runs privileged when necessary
  - ? Works on all POSIX systems

What Doesn't Work
  - ? Cannot drop privileges if ICMP monitoring is enabled
  - ? Most sysmon deployments use PING checks -> run as root
  - ? Security benefit limited to ICMP-free deployments

Current Behavior

`c
void revoke_root_if_necessary()
{
    // Check if running as root
    if (geteuid() != 0) return;

    // CRITICAL: Cannot drop if ICMP enabled
    if (!disable_icmp) {
        print_err("ICMP enabled - must retain root for ICMP send");
        return;  // Still running as root!
    }

    // Only reaches here if ICMP disabled
    setgid(nobody); setuid(nobody);
}
`

Result: Most deployments still run as root (ICMP is commonly used).

  - --

Why ICMP Requires Privileges

Raw Sockets
ICMP uses raw sockets (SOCK_RAW) which require special privileges:

`c
// In setup_icmp_fd()
glob_icmp_fd = socket(AF_INET, SOCK_RAW, IPPROTO_ICMP);
// Requires CAP_NET_RAW or euid=0
`

Socket Creation vs Packet Sending
  - socket() - Only needs privileges at creation time
  - sendto() - ALSO needs privileges for each ICMP packet send

Problem: Can't drop privileges after socket creation because sendto() also requires them.

Solution 1: Linux Capabilities (Best)

Overview
Linux capabilities allow fine-grained privilege control - keep only what's needed.

Implementation

`c
ifdef __linux__
include <sys/capability.h>
include <sys/prctl.h>

void revoke_root_with_capabilities()
{
    cap_t caps;
    cap_value_t cap_list[2] = {CAP_NET_RAW, CAP_NET_BIND_SERVICE};
    uid_t target_uid;

    // Look up 'nobody' user
    struct passwd *pw = getpwnam("nobody");
    if (!pw) return;
    target_uid = pw->pw_uid;

    // Create capability set with only what we need
    caps = cap_init();

    // Set permitted and effective capabilities
    cap_set_flag(caps, CAP_PERMITTED, 2, cap_list, CAP_SET);
    cap_set_flag(caps, CAP_EFFECTIVE, 2, cap_list, CAP_SET);

    // Apply capabilities
    if (cap_set_proc(caps) != 0) {
        perror("cap_set_proc");
        cap_free(caps);
        return;
    }

    // Drop to non-root user while KEEPING capabilities
    if (prctl(PR_SET_KEEPCAPS, 1, 0, 0, 0) != 0) {
        perror("prctl PR_SET_KEEPCAPS");
        cap_free(caps);
        return;
    }

    // Change user/group
    setgid(pw->pw_gid);
    setuid(target_uid);

    // Re-apply capabilities (lost during setuid)
    if (cap_set_proc(caps) != 0) {
        perror("cap_set_proc after setuid");
        cap_free(caps);
        return;
    }

    cap_free(caps);

    print_err(0, "Dropped to uid=%d with CAP_NET_RAW + CAP_NET_BIND_SERVICE",
              getuid());
}
endif / __linux__ /
`

Benefits
  - ? Works with ICMP enabled
  - ? Only keeps 2 capabilities (vs all 40+ as root)
  - ? Can send ICMP packets
  - ? Can bind privileged ports
  - ? Cannot access files as root
  - ? Cannot kill arbitrary processes
  - ? Cannot modify system config

Limitations
  - ? Linux-specific (won't work on BSD, Solaris, macOS)
  - ? Requires libcap (-lcap linker flag)
  - ? More complex than simple setuid()

Build System Changes Needed

configure.in:
`bash
AC_CHECK_LIB(cap, cap_init, [
    LIBS="$LIBS -lcap"
    AC_DEFINE(HAVE_LIBCAP, 1, [Define if you have libcap])
])
`

src/Makefile:
`makefile
LIBS += -lcap  # If HAVE_LIBCAP
`

Runtime check:
`c
ifdef HAVE_LIBCAP
    revoke_root_with_capabilities();
else
    revoke_root_if_necessary();  // Fallback
endif
`

Solution 2: File Capabilities (Deployment-Time)

Overview
Set capabilities on the sysmond binary itself - doesn't require running as root.

Implementation

`bash
As root, set file capabilities on binary
setcap 'cap_net_raw,cap_net_bind_service=+ep' /usr/local/bin/sysmond

Now sysmond can run as regular user
su -c '/usr/local/bin/sysmond' nobody
`

Benefits
  - ? No code changes needed
  - ? Sysmon never runs as root
  - ? System admin controls via file permissions
  - ? Can still send ICMP and bind privileged ports

Limitations
  - ? Linux-specific
  - ? Capabilities lost if binary is replaced (e.g., during upgrade)
  - ? Some filesystems don't support extended attributes

Recommended for
  - Docker/container deployments
  - Security-conscious environments
  - When building from source

  - --

Solution 3: Systemd Socket Activation

Overview
Systemd creates sockets as root, passes file descriptors to unprivileged sysmond.

Implementation

sysmond.socket:
`ini
[Unit]
Description=Sysmon Listening Socket
Before=sysmond.service

[Socket]
ListenStream=3334
ListenDatagram=3334
Accept=no

[Install]
WantedBy=sockets.target
`

sysmond.service:
`ini
[Unit]
Description=Sysmon Network Monitor
Requires=sysmond.socket
After=sysmond.socket

[Service]
Type=simple
User=nobody
Group=nogroup
ExecStart=/usr/local/bin/sysmond --socket-activation
Restart=on-failure

Still need CAP_NET_RAW for ICMP
AmbientCapabilities=CAP_NET_RAW

[Install]
WantedBy=multi-user.target
`

Code changes:
`c
void setup_client_listen_socket_activation()
{
    // Get socket FD from systemd
    int fd = SD_LISTEN_FDS_START;  // Usually fd=3

    // Verify it's a socket
    if (sd_is_socket(fd, AF_UNSPEC, SOCK_STREAM, 1)) {
        glob_listen_fd = fd;
        print_err(0, "Using socket-activated FD %d", fd);
    }
}
`

Benefits
  - ? Never runs as root
  - ? Socket binding handled by systemd
  - ? Standard systemd approach
  - ? Can restart without losing connections

Limitations
  - ? Systemd-specific (Linux only)
  - ? Doesn't solve ICMP problem (still needs CAP_NET_RAW)
  - ? More complex deployment

Solution 4: Separate Ping Helper (Portable)

Overview
Small setuid helper program just for ICMP, main daemon unprivileged.

Implementation

ping_helper.c:
`c
/ Setuid root helper - ONLY sends ICMP, nothing else /
int main(int argc, char argv)
{
    // Drop privileges immediately after sending
    struct icmp_request req;

    // Read request from stdin (from sysmond)
    read(STDIN_FILENO, &req, sizeof(req));

    // Open ICMP socket (requires root)
    int fd = socket(AF_INET, SOCK_RAW, IPPROTO_ICMP);

    // Send packet
    sendto(fd, req.packet, req.len, 0, ...);

    // Drop privileges IMMEDIATELY
    setuid(getuid());

    // Exit
    close(fd);
    return 0;
}
`

sysmond integration:
`c
void send_icmp_via_helper(struct icmp_packet *pkt)
{
    int pipefd[2];
    pipe(pipefd);

    pid_t pid = fork();
    if (pid == 0) {
        // Child: exec helper
        dup2(pipefd[0], STDIN_FILENO);
        execl("/usr/local/libexec/sysmon-ping-helper", ...);
    }

    // Parent: send packet data to helper
    write(pipefd[1], pkt, sizeof(*pkt));
    waitpid(pid, NULL, 0);
}
`

Benefits
  - ? Works on all POSIX systems
  - ? Main daemon runs unprivileged
  - ? Minimal attack surface (tiny helper)
  - ? Helper can be audited separately

Limitations
  - ? Performance: fork/exec overhead for every ping
  - ? Complex: IPC, process management
  - ? Deployment: Need to install + setuid helper binary

  - --

Recommended Approach

Short Term (Current Implementation)
`
if (ICMP disabled)
    drop to nobody
else
    stay as root + warn user
`

Pro: Works now, no dependencies
Con: Most deployments still root

Medium Term (6-12 months)
Linux: Implement Solution 1 (capabilities)
Others: Current implementation

`c
ifdef HAVE_LIBCAP
    drop_to_nobody_with_cap_net_raw();
else
    revoke_root_if_necessary();  // Current code
endif
`

Pro: Secure on Linux (majority of deployments)
Con: Still root on BSD/macOS

Long Term (1-2 years)
All platforms: Solution 4 (ping helper)

Pro: Secure everywhere
Con: Complex, needs testing
