Security Patch Summary: strcpy/strcat Fixes

Overview

This patch addresses all 26 instances of unsafe strcpy() and strcat() functions identified in the security analysis. The patch uses defense-in-depth approaches including bounds checking, safe alternatives, and length tracking.

Changes by File

1. src/syswatch.c (CRITICAL)

Lines 273-281: Command-line argument parsing
  - Original vulnerability: strcpy(conf_file, argv[x]+2) - no bounds checking on user input
  - Fix: Replaced with snprintf(conf_file, 256, "%s", argv[x]+2)
  - Impact: Prevents buffer overflow from malicious command-line arguments

Line 1888: Config file path initialization
  - Original vulnerability: strcpy(configfile, CFILE) - assumes CFILE macro is short enough
  - Fix: Replaced with snprintf(configfile, sizeof(configfile), "%s", CFILE)
  - Impact: Prevents overflow if sysconfdir path is long

2. src/client.c (CRITICAL)

Line 78: Hostname parsing from network data
  - Original vulnerability: strcpy(stuff->hostname, space) - no verification of source length
  - Fix:
  `c
  strncpy(stuff->hostname, space, sizeof(stuff->hostname) - 1);
  stuff->hostname[sizeof(stuff->hostname) - 1] = '\0';
  `
  - Impact: Prevents remote buffer overflow via crafted packets

Lines 147, 288: Time string handling
  - Original vulnerability: strcpy(nfo, ctime(&t)+4) - fragile pointer arithmetic
  - Fix: Replaced with strftime(nfo, sizeof(nfo), "%b %d %H:%M:%S %Y", localtime(&t))
  - Impact: More robust and safer time formatting

Lines 319, 324, 327: Server name from environment/argv
  - Original vulnerability: strcpy(server, argv[1]) and strcpy(server, temp) - no bounds checking
  - Fix: Replaced with snprintf(server, sizeof(server), "%s", source)
  - Impact: Prevents stack-based buffer overflow from environment variables or arguments

3. src/page.c (HIGH RISK)

Lines 68-165: Message template expansion
  - Original vulnerability: 15 chained strcat() calls into 1024-byte buffer
  - Fixes implemented:
  1. Increased buffer size from 1024 to 4096 bytes
  2. Added current_len tracking variable
  3. Replaced all strcat() with bounds-checked strncat()
  4. Each concatenation checks: if (current_len + len < sizeof(out))

  - Example fix:
  `c
  // Before:
  strcat(out, myhostname);

  // After:
  if (current_len + strlen(myhostname) < sizeof(out)) {
      strncat(out, myhostname, sizeof(out) - current_len - 1);
      current_len += strlen(myhostname);
  }
  `

  - Time handling improvements: Replaced ctime() pointer arithmetic with strftime()
  `c
  // Before:
  strcat(out, ctime(&t)+4);
  out[strlen(out)-6]='\0';

  // After:
  char date_str[32];
  strftime(date_str, sizeof(date_str), "%b %d %H:%M:%S", localtime(&t));
  if (current_len + len < sizeof(out)) {
      strncat(out, date_str, sizeof(out) - current_len - 1);
      current_len += len;
  }
  `

  - Impact: Prevents buffer overflow in notification message generation

4. src/srvclient.c (MEDIUM)

Line 827: IP address storage
  - Original vulnerability: strcpy(thisclient->ip, inet_ntoa(remote.sin_addr))
  - Fix: Replaced with snprintf(thisclient->ip, 20, "%s", inet_ntoa(remote.sin_addr))
  - Impact: Defensive programming against any unexpected behavior

5. src/radius.c (LOW)

Line 375: Fixed string copy
  - Original vulnerability: strcpy(packet+packetindex, "sysmon")
  - Fix: Replaced with memcpy(packet+packetindex, "sysmon", 6)
  - Impact: More explicit about fixed-length binary data copy

6. src/loadconfig.c (MEDIUM)

Line 157: Variable replacement
  - Original vulnerability: strcat(new_string, repl) - unbounded concatenation
  - Fix: Added length tracking and bounds checking:
  `c
  size_t repl_len = strlen(repl);
  if (current_len + repl_len < MAX_STRLEN) {
      strncat(new_string, repl, MAX_STRLEN - current_len - 1);
      current_len += repl_len;
  }
  `
  - Impact: Prevents overflow from excessive variable replacements in config files

Security Improvements

Defense-in-Depth Strategy

1. Bounds Checking: Every string operation now checks buffer size
2. Explicit Sizing: Using sizeof() instead of magic numbers
3. Null Termination: Explicit null termination with strncpy()
4. Length Tracking: For multiple concatenations, track cumulative length
5. Safe Alternatives: Using snprintf(), strftime(), memcpy() where appropriate

Additional Benefits

  - Thread Safety: Replaced ctime() (not thread-safe) with strftime() + localtime()
  - Maintainability: More explicit code that's easier to audit
  - Compiler Warnings: Modern compilers will catch some issues with new code
  - Buffer Size Increase: page.c buffer increased 1024->4096 bytes for additional safety margin

Remaining Concerns

While this patch addresses all identified strcpy/strcat issues, consider:

1. sprintf usage: Audit for unsafe sprintf() calls (should use snprintf())
2. gets() function: Should never be used (already deprecated)
3. Manual buffer operations: Review any manual pointer arithmetic
4. Third-party libraries: Audit dependencies for similar issues
