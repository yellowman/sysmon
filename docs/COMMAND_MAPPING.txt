Sysmon Web UI Command Mapping

This document maps all sysmon TCP protocol commands to their appropriate web UI pages.

Commands Already Implemented

Dashboard Page
  - STAT - Get status list of all objects ? IMPLEMENTED
  - Used in GetStatus() to populate host list
  - Shows overall status, check counts, etc.

  - SHOWOBJ <objectname> - Get detailed object XML ? IMPLEMENTED
  - Used in GetStatus() to get detailed info per host
  - Returns ObjectState, ObjectContacted, check history, etc.

  - ACK <objectname> - Acknowledge alert ? IMPLEMENTED
  - Blue "Ack" button on each alert
  - Sets obj->data->acked = TRUE

  - UPD <objectname> <note> - Update with status note ? IMPLEMENTED
  - Green "Update" button with modal dialog
  - Sets obj->data->notes = user note

  - MODE xml - Enable XML output mode ? IMPLEMENTED
  - Sent before all SHOWOBJ, ACK, UPD commands
  - Required for structured data parsing

SNMP Traps Page
  - Shows recent SNMP traps received (from SHOWOBJ data)

Configuration Page
  - Config file editing and validation
  - Backup/restore functionality

Commands To Be Implemented

1. Hosts Page Enhancements

TRACE <objectname> - Toggle per-object tracing
  - Location: Add toggle button/checkbox to each host row
  - Auth Level: None required
  - Function: Enables verbose logging for specific host
  - Implementation:
  - Button shows current state (Tracing: ON/OFF)
  - Click toggles trace flag
  - Visual indicator when tracing is active
  - Useful for debugging specific host issues

CONF - Get all object configurations
  - Location: Add "Export All Configs" button
  - Auth Level: Required (authlvl > 0)
  - Function: Returns XML configuration for all objects
  - Implementation:
  - Download button that fetches all configs
  - Saves as XML file
  - Useful for backup/documentation

2. New "Admin & Diagnostics" Page

This page provides system administration and debugging tools.

System Information (Read-Only)

VERS - Get daemon version
  - Display: Version badge at top of admin page
  - Auth Level: None required
  - Example: "Sysmon v0.94"

UPTIME - Get daemon uptime
  - Display: Uptime counter (auto-refreshing)
  - Auth Level: None required
  - Format: "X days, Y hours, Z minutes"
  - Already available in daemon.uptime_seconds from STATUS

Debug Controls (Admin Only - authlvl > 1)

DEBUG - Toggle general debugging
  - UI: Toggle switch "General Debug Logging"
  - Auth Level: Required (authlvl > 1)
  - Function: Enables verbose debug output to syslog
  - Warning: "May generate large log files"

SNMPD - Toggle SNMP debugging
  - UI: Toggle switch "SNMP Debug Logging"
  - Auth Level: Required (authlvl > 1)
  - Function: Enables SNMP-specific debug output
  - Warning: "May generate large log files"

Diagnostic Commands (Admin Only)

EXPIREDNS - Expire DNS cache
  - UI: Button "Clear DNS Cache"
  - Auth Level: Required (authlvl > 1)
  - Function: Forces re-resolution of all hostnames
  - Use Case: When DNS records change
  - Confirmation: "Are you sure? This will re-resolve all hostnames."

PRINTQ - Print internal queue
  - UI: Button "Show Internal Queue"
  - Auth Level: Required (authlvl > 1)
  - Function: Displays internal check queue state
  - Output: Shows queued checks, processing state
  - Display: In scrollable text area / modal

NFD - Show next file descriptor info
  - UI: Button "Show FD Info"
  - Auth Level: Required (authlvl > 1)
  - Function: Shows next available FD and queue depth
  - Output: "X is the next FD - Y queued"
  - Use Case: Debugging resource exhaustion

System Control (Admin Only)

KILLIT - Gracefully shutdown daemon
  - UI: Red button "Shutdown Daemon"
  - Auth Level: Required (authlvl > 1)
  - Function: Stops daemon gracefully (stop_daemon = TRUE)
  - Warning: DANGER ZONE - Big red button
  - Confirmation: Multi-step confirmation required
  1. "Are you sure you want to shutdown sysmon?"
  2. Type "SHUTDOWN" to confirm
  - Note: May require service manager restart

  - --

Commands NOT Exposed in Web UI

These commands are for protocol management and should not be exposed:

NOOP - No operation / keep-alive
  - Use: Protocol keep-alive, connection testing
  - Reason: Internal connection management only

QUIT - Close connection
  - Use: Gracefully close TCP connection
  - Reason: Handled automatically by HTTP/TCP layer

AUTH - Authenticate client
  - Use: Set authentication level
  - Reason: Will be implemented via proper web authentication
  - Future: Use HTTP auth headers, session cookies, etc.

GET - HTTP fallback handler
  - Use: Handle accidental browser connections
  - Reason: Legacy compatibility for direct TCP connections

STATO - Status with outage flag
  - Use: Variant of STAT command
  - Reason: Internal flag, can be merged into STAT implementation

ABORT - Force core dump
  - Use: Emergency debugging
  - Reason: TOO DANGEROUS - could crash production system
  - Alternative: Use system debugging tools if needed

  - --

Web UI Page Structure

`
/                        Dashboard (hosts status, alerts, ACK/UPD)
/hosts.html              Hosts (list with TRACE toggles, CONF export)
/traps.html              SNMP Traps (recent traps display)
/config.html             Configuration (edit, validate, backup/restore)
/admin.html              Admin & Diagnostics (NEW - system controls)
`

Authentication Strategy

Current implementation has no authentication. Future considerations:

1. Read-Only Access (authlvl = 0)
  - STAT, SHOWOBJ, VERS, UPTIME, TRACE
  - Dashboard, Hosts, Traps pages

2. Standard Access (authlvl = 1)
  - ACK, UPD, CONF
  - Configuration page (read-only or limited edits)

3. Admin Access (authlvl > 1)
  - DEBUG, SNMPD, EXPIREDNS, PRINTQ, NFD, KILLIT
  - Admin page, full config editing

Implementation Priority

Phase 2 (Medium Priority)
4. DEBUG, SNMPD toggles

6. CONF export functionality

Phase 3 (Low Priority)
7. KILLIT shutdown with heavy confirmation
8. Authentication/authorization system

Security Considerations

1. KILLIT command - Requires multi-factor confirmation
2. Debug toggles - Warn about log volume
3. EXPIREDNS - May cause temporary service interruption
4. PRINTQ, NFD - May expose internal state
5. CONF - May expose sensitive configuration data

Notes

  - All admin commands should log who executed them and when
  - Consider adding audit trail for destructive operations
  - KILLIT should have cooldown period or rate limiting
  - Debug toggles should auto-disable after timeout (e.g., 1 hour)
